# NEXUS 前端界面统一与体验改进方案

> 状态：Draft
> 编写日期：2026-08-17
> 范围：首页、知识库、GitLab、Wiki、版本中心、代码工作台
> 目标：降低视觉噪声，统一导航和交互，使核心任务更容易完成
>
> 2026-08-17 范围调整：版本对比不再作为 0.9.1 核心需求，旧 `/versions` 页面和 API
> 仅兼容保留；代码工作台采用完整浅色工作区，不再保留深色图画布。

## 1. 结论

当前界面“乱”并不是单个页面样式不好，而是多个页面分别演进，形成了四套产品语言：

1. 首页是米色、衬线大标题和大卡片的展示页。
2. Wiki 与版本中心是米色三栏阅读器。
3. 知识库与 GitLab 是白底、紧凑表格的管理后台。
4. 代码工作台是高密度深色控制台。

这些页面在导航、字体、色板、圆角、间距、错误提示和移动端策略上都不一致。用户每次切换
页面都需要重新学习一次界面。

建议将 NEXUS 定义为“知识与代码运营工作台”，统一使用一个安静、紧凑的应用外壳：

- 所有页面共享同一主导航、项目上下文和状态语言。
- 运维页面采用浅色工作台。
- 只有代码图画布保持深色，作为产品的视觉特征。
- Wiki 的正文区域可以保留有限的衬线字体，但导航和控件必须统一。
- 首页改成可操作的运行总览，不再承担营销落地页角色。

## 2. 分析依据

本方案基于 CodeGraph、当前静态资源和实际桌面/移动端页面截图。

当前前端规模：

| 页面 | 当前规模 | 主要问题 |
|---|---:|---|
| `home.html` | 约 6.8 KB | 展示感过强，操作入口与运行状态分离 |
| `knowledge.html` | 约 14.8 KB | 信息优先级接近，移动导航不完整 |
| `gitlab-settings.html` | 约 9 KB | 与知识库共用样式，但缺少全局产品上下文 |
| `wiki.html` | 约 29 KB | 独立色板和导航，移动端头部拥挤 |
| `versions.html` | 约 19 KB | 独立色板和导航，空状态占据大面积 |
| `monitor.html` | 约 113 KB、2427 行 | 控件过密，视觉和其他页面完全割裂 |

另外：

- 5 个 HTML 文件各自内嵌整套 `<style>`。
- 小于等于 12px 的文字规则超过 70 处。
- API Key 在 Wiki、版本中心、代码工作台分别出现。
- 每个页面独立维护导航链接和移动端行为。
- 知识库移动端直接隐藏后两项导航，没有替代菜单。
- Wiki 使用固定悬浮“管理知识库”按钮，会和头部内容竞争空间。
- 代码工作台会把后端返回的原始 HTML 错误直接显示在通知中。

## 3. 当前问题清单

### 3.1 P0：导航不一致且移动端丢失入口

当前表现：

- 首页头部只有“代码工作台”。
- 知识库和 GitLab 有完整横向导航。
- Wiki 和版本中心只有部分链接。
- 代码工作台又使用另一套紧凑导航。
- 知识库在小屏幕直接隐藏“版本中心”和“代码工作台”。

影响：

- 用户无法形成稳定的产品地图。
- 移动端存在功能不可发现问题。
- 页面之间的返回路径不明确。

改进：

- 所有业务页面使用同一个全局顶部栏。
- 移动端使用菜单按钮打开完整导航，禁止直接隐藏重要入口。
- 当前页面、当前项目和当前版本始终有明确位置。

### 3.2 P0：错误提示遮挡内容且错误信息不可读

实际观察：

- 知识库移动端的错误通知会覆盖页面标题。
- Wiki 与版本中心同时显示页面错误和右下角通知，形成重复反馈。
- 代码工作台会显示完整的 404 HTML。
- “请求失败”“File not found”没有告诉用户下一步做什么。

改进：

- 建立统一错误对象：

```json
{
  "code": "KNOWLEDGE_API_UNAVAILABLE",
  "message": "知识状态服务暂时不可用",
  "action": "检查服务状态或稍后重试",
  "correlationId": "..."
}
```

- 前端统一清理 HTML、堆栈、内部路径和命令输出。
- 页面初始化失败使用内容区错误状态。
- 后台操作失败使用不遮挡标题的通知。
- 同一个错误只出现一次。
- 通知必须提供“重试”“查看服务状态”等明确操作。

### 3.3 P1：视觉身份分裂

当前页面同时存在：

- 米色与绿色的阅读风格。
- 白色与青色的管理后台风格。
- 深蓝与荧光青的代码控制台风格。
- 6px、10px、15px、22px 等多套圆角。
- Georgia、Songti、Inter、Avenir Next 和系统字体混用。

改进：

- 统一应用外壳、控件和状态颜色。
- 阅读内容与代码画布可以保留场景差异，但必须嵌入同一个产品框架。
- 衬线字体只用于 Wiki 正文标题，不用于管理页面、导航和按钮。

### 3.4 P1：信息密度两极化

首页：

- 标题过大。
- 入口卡片过高。
- 首屏没有直接展示需要处理的问题。

代码工作台：

- 导航、意图模式、图类型、过滤器、搜索和工具操作同时挤在顶部。
- 10px、11px 文本过多。
- 移动端只是缩小桌面布局，并没有重新组织任务。

知识库：

- 页面标题、摘要数字、筛选栏和表格都使用相近的视觉重量。
- 用户无法第一眼判断“当前最需要处理什么”。

改进：

- 首页降低密度，但首屏直接提供操作。
- 管理页面保持紧凑表格，减少重复标题和说明。
- 代码工作台按任务分组，只显示当前模式需要的控制项。

### 3.5 P1：页面结构重复且难以统一

当前：

- 首页、Wiki、版本中心、代码工作台各自内嵌 CSS。
- 知识库和 GitLab 共享 CSS，但其他页面不使用。
- API Key、错误处理、通知、状态标签和导航重复实现。

影响：

- 一个导航调整需要修改多个文件。
- 同一种状态在不同页面可能使用不同颜色和文案。
- 页面越增加，视觉漂移越严重。

## 4. 设计方向

### 4.1 产品定位

对象：需要管理需求知识、代码索引和版本证据的研发团队。
页面的主要任务：快速判断状态、找到异常、进入证据或执行操作。

设计关键词：

- 安静。
- 可扫描。
- 可追溯。
- 操作明确。
- 技术感来自信息结构，不来自装饰。

### 4.2 视觉策略

主界面使用浅色运营工作台，减少米色和深蓝的大面积占用。

建议色板：

| Token | 颜色 | 用途 |
|---|---|---|
| `--canvas` | `#F4F6F5` | 页面背景 |
| `--surface` | `#FFFFFF` | 表格、面板、抽屉 |
| `--ink` | `#17211F` | 主要文本 |
| `--muted` | `#66716D` | 辅助文本 |
| `--action` | `#0B6B5B` | 主操作、成功状态 |
| `--info` | `#286B9E` | 运行中、链接 |
| `--warning` | `#9A650B` | 偏离、待更新 |
| `--danger` | `#B14545` | 失败、危险操作 |
| `--code-canvas` | `#071018` | 代码图画布专用 |

不要使用：

- 大面积米黄色背景。
- 整页深色主题。
- 装饰性渐变和光球。
- 大量阴影卡片。
- 每个区块都包一层卡片。

### 4.3 字体与字号

应用外壳和操作界面：

```css
font-family:
  Inter,
  "PingFang SC",
  "Microsoft YaHei",
  system-ui,
  sans-serif;
```

Wiki 正文标题可使用：

```css
font-family: "Songti SC", "STSong", serif;
```

代码、commit、ID：

```css
font-family: ui-monospace, SFMono-Regular, Menlo, monospace;
```

统一字号：

| 场景 | 字号 |
|---|---:|
| 页面标题 | 28px |
| 紧凑页面标题 | 24px |
| 区域标题 | 18px |
| 表格和正文 | 14px |
| 控件标签、辅助信息 | 12px |
| 最小可见文字 | 12px |

10px、11px 只允许用于极少量图表标注，不用于核心操作和状态说明。

### 4.4 间距与尺寸

使用统一的 4px 基础网格：

```text
4 / 8 / 12 / 16 / 24 / 32
```

建议约束：

- 顶部栏：56px。
- 默认按钮：36px。
- 紧凑图标按钮：32px。
- 输入框：36px。
- 表格行：48 至 56px。
- 面板圆角：6px。
- 抽屉和弹窗圆角：8px。
- 页面最大宽度：1440px。
- 页面水平边距：桌面 24px，移动端 16px。

### 4.5 NEXUS 的识别性元素

保留一个有业务含义的视觉签名：**来源到发布状态带**。

```text
来源 ─ 解析 ─ 分块 ─ 向量化 ─ 索引 ─ 验证 ─ 发布
```

它可以用于：

- 知识文档处理阶段。
- GitLab 仓库同步阶段。
- 代码索引阶段。
- Wiki 生成阶段。

其他装饰保持克制，让这一条状态带成为 NEXUS 最容易识别的交互语言。

## 5. 统一应用外壳

### 5.1 桌面导航

```text
┌────────────────────────────────────────────────────────────────────┐
│ NX NEXUS │ 总览  知识库  Wiki  版本  代码  GitLab │ 项目 ▾  状态  ⚙ │
└────────────────────────────────────────────────────────────────────┘
```

结构：

- 左侧：品牌与返回总览。
- 中间：稳定的一级导航。
- 右侧：项目上下文、系统状态、设置菜单。

API Key 不再直接占据页面头部。移动到“连接设置”弹层：

```text
设置
├── API 连接
├── GitLab 集成
└── 服务状态
```

### 5.2 移动导航

```text
┌──────────────────────────────┐
│ ☰  NEXUS          项目 ▾  ● │
└──────────────────────────────┘
```

菜单展开后显示所有页面，不允许通过 CSS 隐藏最后几项导航。

### 5.3 页面上下文

一级导航下方使用轻量上下文栏：

```text
封神项目 / 知识库 / 版本 5.1
```

项目、版本和 commit 选择应尽量共享 query string：

```text
?projectId=fengshen&version=5.1
```

用户从 Wiki 切到版本中心或代码工作台时，尽可能保留当前项目。

## 6. 页面改进方案

### 6.1 首页：从展示页改为运行总览

当前问题：

- 巨型标题消耗首屏。
- 模块入口像营销卡片。
- 项目异常和待处理任务需要向下滚动才能看到。

目标：

```text
┌────────────────────────────────────────────────────────────────────┐
│ 运行总览                                        最近刷新 14:32  ↻ │
├──────────┬──────────┬──────────┬──────────┬───────────────────────┤
│ 项目 12  │ 就绪 9   │ 处理中 2 │ 失败 1   │ Qdrant ● Ollama ●    │
├──────────────────────────────────────┬─────────────────────────────┤
│ 需要处理                             │ 快速操作                    │
│ ! admin-web 索引失败       [查看]    │ + 接入 GitLab               │
│ ◐ game-client 正在索引     72%       │ ↻ 重建知识库                │
│ ! 3 个知识文档解析失败     [重试]    │ ⌕ 测试检索                  │
├──────────────────────────────────────┴─────────────────────────────┤
│ 项目状态表                                                         │
└────────────────────────────────────────────────────────────────────┘
```

改动：

- 删除大 Hero。
- 删除 220px 高的模块卡片。
- 页面标题改为 28px。
- 首屏优先展示异常、运行中任务和快速操作。
- 模块入口改为全局导航，不在正文重复五张大卡片。
- 服务健康状态压缩为一行，不为每个服务创建大卡片。

### 6.2 知识库：强化扫描与异常定位

保留当前表格方向，但调整层级。

改动：

- 删除英文 `KNOWLEDGE OPERATIONS` 眉题，或改为极弱的上下文标签。
- 汇总数字从大块区域改成 56px 高的紧凑统计栏。
- “处理中”和“失败”有值时才使用强调色。
- 筛选栏吸附在表格顶部。
- 搜索输入靠左，与用户的扫描顺序一致。
- 将“重新构建”放入页面操作菜单，避免与日常查看同权。
- 错误通知不覆盖页面标题。
- 表格在小屏幕转换为行列表，而不是保留 860px 宽表格横向滚动。

知识库详情：

- 左侧阶段栏默认 240px，可折叠。
- 分块状态使用统一状态带。
- `D/S/Q` 改为带 Tooltip 的图标或“稠密/稀疏/已验证”文本。
- 分块抽屉显示正文摘要、来源和错误操作，不只显示元数据。
- 长 ID 默认显示短值，点击复制完整值。

### 6.3 GitLab：让配置过程更像任务，而不是表单集合

项目列表：

- 与知识库列表使用同一表格、筛选和状态组件。
- 将“索引 commit”和“目标 commit”合并为版本状态：

```text
已同步    a15c9d2
偏离      a15c9d2 → c933fa1
旧版可用  a15c9d2
```

- 失败行直接提供“查看原因”和“重试”。

接入向导：

- 步骤栏保持固定，但每一步只显示当前任务需要的字段。
- 普通字段与高级字段分开。
- collection 默认自动生成，高级设置默认折叠。
- 连接测试结果显示为检查清单，而不是单行绿色文字。
- Webhook Secret 增加显示/隐藏、复制和已复制反馈。
- 第五步创建后原地展示首次同步状态带。

项目详情：

- 顶部只保留“同步”和操作菜单。
- “停用”进入操作菜单并使用二次确认弹窗。
- 时间线显示阶段、耗时、commit 和错误，不用点击后再以通知拼接阶段名称。
- Webhook 状态放在右侧诊断栏。

### 6.4 Wiki：统一外壳，保留阅读体验

当前问题：

- 固定悬浮“管理知识库”按钮与头部重叠。
- 三栏布局在窄屏直接折叠，缺少目录返回逻辑。
- 页面控件和管理后台不是同一套样式。

改动：

- 删除右上角固定悬浮按钮。
- “管理知识库”进入全局导航或页面操作菜单。
- 全局头部使用统一应用外壳。
- Wiki 内部保留：

```text
功能目录 | 正文 | 证据
```

- 左侧目录可折叠。
- 右侧证据在 1180px 以下变为抽屉，而不是永久消失。
- 移动端进入正文后，顶部提供“返回目录”和“查看证据”。
- 正文标题可保留衬线字体，控件全部使用统一无衬线字体。
- `重新生成当前版本` 属于写操作，移到操作菜单并明确权限。

### 6.5 版本中心：把比较操作放到主内容区

当前问题：

- 300px 左栏在没有版本数据时占据大量空间。
- 页面大面积空白。
- 头部导航与其他页面不同。

改动：

- 项目、起始版本、目标版本组成顶部比较栏。
- 版本时间线作为可折叠左栏，只在存在多个版本时显示。
- 比较结果首屏显示来源可用性和关键变化，不先显示大标题。
- 四类差异使用相同的标签、空状态和错误状态。
- 移动端将比较条件变成顶部折叠面板。

目标结构：

```text
项目 [封神 ▾]  从 [5.0 ▾]  到 [5.1 ▾]  [比较]
来源状态：需求 ● 代码 ● 测试 ! Wiki ●
需求变化 | 代码变化 | 测试变化 | Wiki 变化
```

### 6.6 代码工作台：保留能力，重新组织控制项

这是改造成本最高的页面。

视觉策略：

- 使用统一浅色应用外壳。
- 代码图画布继续使用深色。
- 右侧信息栏可保持深色或改为中性浅色，但不要整页深色。

控制项分为三层：

1. 页面模式：理解代码 / 开发方案。
2. 查询输入：搜索框和开始按钮。
3. 图谱选项：视图、过滤、自动识别，放入可折叠工具栏。

桌面：

```text
┌────────────────────────────────────────────────────────────────────┐
│ 代码工作台 / 封神服务                              索引 ● a15c9d2 │
├────────────────────────────────────────────────────────────────────┤
│ [理解代码 | 开发方案] [搜索____________________] [开始] [筛选 ⚙] │
├───────────────────────────────────────────┬────────────────────────┤
│                                           │ 信息 | 文件 | 证据     │
│              深色代码图画布               │                        │
│                                           │ 当前节点详情           │
└───────────────────────────────────────────┴────────────────────────┘
```

改动：

- 顶部不同时展示全部模式、视图、节点类型和图例。
- 图例放入画布角落，可折叠。
- 高级筛选进入 Popover。
- 自动识别改成开关，不使用文本按钮。
- 右侧栏标签改成稳定的三项，减少状态变化时跳动。
- 原始错误 HTML 必须经过统一错误规范化。
- 通知最大两行，详细错误进入诊断抽屉。
- 12px 以下文字全部复核。

移动端不展示桌面双栏：

```text
[查询]
[图谱] [信息] [文件] [证据]
```

- 图谱和侧栏使用全屏 Tab 切换。
- 工具栏放入底部 Sheet。
- 不在 390px 宽度同时显示图画布和右侧栏。

### 6.7 技术简报

`tech-briefing.html` 属于演示/阅读场景，可以保留独立版式，但应：

- 使用统一 NEXUS 品牌入口。
- 提供明确返回工作台操作。
- 复用统一颜色 Token 和焦点样式。
- 不影响核心应用 CSS。

## 7. 统一状态与反馈

### 7.1 状态词汇

所有页面只使用以下稳定词汇：

| 状态 | 文案 |
|---|---|
| `IDLE` | 未开始 |
| `QUEUED` | 排队中 |
| `RUNNING` | 处理中 |
| `READY` | 就绪 |
| `PARTIAL` | 部分完成 |
| `STALE` | 待更新 |
| `FAILED` | 失败 |
| `DISABLED` | 已停用 |

不要在不同页面使用“成功”“可用”“已同步”“完成”表示同一底层状态，除非业务语义确实不同。

### 7.2 通知

桌面：

- 位于顶部栏下方右侧。
- 不遮挡标题和主要操作。
- 最大宽度 420px。
- 最多显示两条。

移动端：

- 位于屏幕底部安全区上方。
- 不覆盖顶部导航和页面标题。
- 提供明确关闭按钮。

### 7.3 空状态

空状态必须回答：

1. 为什么为空。
2. 用户下一步能做什么。

示例：

```text
尚未生成知识分块
当前版本还没有完成知识导入。
[开始构建] [查看导入配置]
```

### 7.4 加载状态

- 首次加载使用骨架屏或区域级加载。
- 不使用整页“正在加载”覆盖已有内容。
- 轮询更新不得让表格和侧栏闪烁。
- 已有数据刷新时只更新状态，不清空列表。

## 8. 响应式规范

### 8.1 断点

```text
Desktop: >= 1200px
Compact: 768px - 1199px
Mobile:  < 768px
```

### 8.2 移动端原则

- 一级导航进入菜单抽屉。
- 主操作固定在可见区域，但不能遮挡内容。
- 表格转换为结构化列表。
- 侧栏转换为抽屉或 Tab。
- 筛选器进入可折叠区域。
- 所有触控目标至少 40px。
- 长 commit 和路径使用省略与复制，不强制撑宽页面。
- 不通过 `display:none` 删除核心功能入口。

4. 统一通知位置，移动端改到底部。

### 12.3 验收标准

- 用户在任意页面都能一次操作进入其他五个核心模块。
- 移动端不丢失任何一级导航。
- 页面切换时品牌、导航、按钮和状态语言保持一致。
- 首屏不存在被通知遮挡的标题或操作。
- 接口返回 HTML 时，前端只显示规范化错误。
- 代码工作台首屏核心控制不超过三组。

- 除代码画布外，不存在整页深色主题。
- 核心文本字号不低于 12px。
- 所有状态同时使用图标、颜色和文本，不只依赖颜色。

## 13. 不建议的做法

- 不引入新的大型 UI 框架来掩盖现有结构问题。
- 不把所有页面改成卡片仪表盘。
- 不让首页继续承担营销落地页角色。
- 不强行把 Wiki 正文和代码画布做成完全相同的视觉风格。
- 不在移动端简单隐藏控件。
- 不在重构界面时同时修改检索、索引和 GitLab 核心业务逻辑。
- 不一次性重写 `monitor.html`，应先建立视觉和错误基础设施。

## 14. 推荐实施顺序

```text
统一错误处理
  -> 统一 Token
  -> 统一导航和移动菜单
  -> 知识库 / GitLab
  -> 首页 / Wiki / 版本中心
  -> 代码工作台
  -> 视觉回归与可访问性
```

最重要的第一个里程碑不是“所有页面变漂亮”，而是：

**用户无论进入哪个页面，都能知道自己在哪里、当前项目是什么、系统处于什么状态，以及下一步能做什么。**

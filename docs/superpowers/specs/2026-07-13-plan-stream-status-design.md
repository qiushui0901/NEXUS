# 开发方案流式状态设计

## 背景

开发方案通过 SSE 接收模型逐段输出。当前页面只区分“生成中”和“非生成中”，导致生成中断时仍显示绿色指示灯。当前 18080 端口同时运行着修改前启动的旧 Java 进程，尚未加载新的流式异常收尾逻辑。

## 状态模型

前端增加独立的 `planStatus`，取值固定为：

- `idle`：尚未生成，灰色。
- `running`：正在检索或生成，蓝色呼吸灯。
- `success`：收到 `completed` 事件，绿色。
- `error`：收到 `error` 事件、HTTP/SSE 读取失败或流结束但未收到完成事件，红色。

状态文案继续由 `planStage` 保存，状态颜色不得依赖中文文案判断。

## 数据流

1. 点击生成时设置 `running`。
2. `started`、`retrieval` 和内容事件保持 `running`。
3. `completed` 设置 `success`。
4. `error` 或请求异常设置 `error`，优先显示服务端返回的简短原因。
5. 用户主动取消旧请求时不误报故障；新请求会立即进入 `running`。

## 界面

状态点保持现有 7px 尺寸：运行中用蓝色呼吸动画，完成用绿色，中断用红色并带轻微红色外圈，等待用灰色。不增加图标和大块警告面板。

## 服务运行

停止当前 18080 旧进程并使用现有 Java 21/Maven 配置重新启动，使 `DevelopmentPlanStreamService` 的有效分段容错逻辑生效。

运行验证发现当前环境把生成模型覆盖为 `claude-sonnet-5`。该模型拒绝 `temperature` 参数，因此开发方案的流式与非流式生成统一使用只设置模型名称的 `GenerationChatOptions`，不再发送 `temperature`。

## 验证

- 静态页面测试覆盖四种状态类和错误映射。
- 流式服务回归测试覆盖“已有有效分段后网关超时仍能正常收尾”。
- 模型选项测试确认开发方案请求的 `temperature` 为 `null`。
- 浏览器验证中断为红灯、完成为绿灯、运行中为蓝灯。
- 完整 Maven 测试保持通过。

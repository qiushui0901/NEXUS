# NEXUS 流式开发方案与源码抽屉设计

## 目标

1. 开发方案由后端通过 SSE 真实逐段返回，前端收到一段就立即展示。
2. 源码从右侧栏移到图谱底部抽屉，支持全屏阅读和恢复。
3. 精简图谱顶部工具区域，并保证卡片文字、代码路径和按钮不会越出边框。

## 方案

采用“POST 请求 + SSE 响应 + NDJSON 模型协议”。模型输出由多行独立 JSON 事件组成，每行只描述一个完整内容单元。后端收到完整行后立即解析并转成 SSE 事件，从而同时满足真实流式和结构化卡片展示。

保留现有 `/api/assistant/development-plan` 接口作为兼容和降级入口，新增 `/api/assistant/development-plan/stream`。

## 后端设计

统一事件结构包含 `type`、`sequence`、`payload` 和 `message`。事件按以下顺序发送：

- `started`：请求已接收。
- `retrieval`：需求文档和代码向量检索完成。
- `summary`：开发切入点。
- `product-understanding`：单条产品规则理解。
- `constraint`：单条开发约束。
- `chain`：单条产品规则到技术环节的映射。
- `section`：单个完整开发环节。
- `implementation-step`：单条实施顺序。
- `risk`：单条风险。
- `references`：相关文档与代码引用。
- `completed`：生成完成。
- `error`：生成失败。

生成流程：控制器立即建立 `text/event-stream`；服务检索 Qdrant 并发送 `retrieval`；模型严格输出一行一个 JSON 对象；`ChatClient.stream().content()` 接收增量文本；后端缓冲不完整行，只解析完整 NDJSON 行并即时发送。

流中断时前端保留已收到内容。单行无法解析时跳过并记录日志，不中断其他内容。客户端重新生成时取消上一条请求。

## 前端开发方案

使用 `fetch` POST 和 `response.body.getReader()` 读取 SSE。顶部显示当前阶段，每收到一个事件就追加到对应区块；尚未返回的区块不预铺空卡片。完成后仍按规则理解、开发约束、链路、开发环节、实施顺序和风险分区。

## 源码抽屉

点击“打开代码”或文件列表后，右侧栏保持当前状态，图谱底部弹出约占视口高度 38% 的源码抽屉，覆盖图谱下部而不改变图谱布局。

抽屉左上显示类型、名称、路径和行号，主体显示带行号源码；右上提供全屏/还原与关闭。全屏采用页面内覆盖层，不申请浏览器原生全屏权限；`Esc` 退出全屏并恢复到底部抽屉。

## 图谱工具区精简

删除整行图例和大按钮工具栏。缩小、适配、放大、只看路径改成画布右上角的紧凑悬浮控制；节点和关系数量放到画布左下角的小型状态文字。

## 防溢出规则

- Grid/Flex 子项统一设置 `min-width: 0`。
- 说明文字使用 `overflow-wrap: anywhere`。
- 文件路径和长类名允许断行。
- 按钮文字不换行，按钮组在窄屏自动换行。
- 开发方案卡片不使用固定高度。
- 代码区只允许自身横向滚动，页面不产生横向滚动。

## 测试与验收

- 流式接口返回 `text/event-stream`，检索事件先于内容事件。
- 多个文本块能拼接成完整 NDJSON 行，无效行不终止流。
- 正常结束发送 `completed`，异常发送 `error`。
- 前端按事件增量渲染，重新生成会取消旧请求。
- 源码抽屉支持打开、全屏、还原、关闭和 `Esc`。
- 1280px 和窄屏下无页面横向溢出，文字不越出卡片。
- 图谱初始适配仍展示全部节点。

# 批处理任务并发与资源配额

## 队列、并发和公平性

批处理平台承载报表、数据转换和离线计算任务。配额按组织、队列和任务类型计算，不按单个用户与项目的组合计算。每个组织有并发槽位和每日计算时长，关键队列预留固定容量。客户端提交的优先级仅作为建议，服务端策略决定最终队列顺序。

任务进入队列前校验输入位置、输出位置、资源规格、镜像和预计时长。校验失败不占用并发槽位。重复提交使用调用方幂等键识别，相同键返回已有任务。修改资源规格需要创建新的任务尝试，不能在运行中扩大 CPU 或内存限制。

软并发阈值达到时，新任务继续进入队列并返回预计等待时间；硬阈值达到时仍接受任务定义，但标记为资源等待，不启动执行器。只有组织达到每日计算时长上限时才拒绝新任务。拒绝响应包含下一计费窗口开始时间，不代表可以立即重试下游。

调度窗口使用服务端单调时间和结算日历。客户端时间、文件时间戳和队列消息时间都不能改变配额窗口。跨时区组织按照配置的结算区域切换日期。日历变更只影响未来窗口，当前窗口保持原边界并记录配置版本。

抢占只用于关键队列。被抢占任务保存检查点并回到队列，不计为失败。连续被抢占三次后提升恢复优先级，但不会绕过组织硬上限。普通任务不能通过拆分为多个小任务规避配额，平台按任务族聚合统计。

## 取消、恢复与监控

用户取消排队任务立即释放预留；取消运行任务先发送终止信号，等待两分钟后强制停止。已经提交的输出分片标记为不完整，下一次重试从最后校验检查点继续。取消不删除任务定义和资源统计，便于审计为何没有产出完整结果。

执行器故障时，调度器根据心跳和租约判断。租约过期的任务进入恢复队列，同一任务同时只能有一个有效执行器。旧执行器恢复连接后必须停止，不能继续写输出。输出提交使用任务、尝试和分片编号保证幂等。

配额服务不可用时暂停启动新任务，正在运行任务继续到当前检查点。恢复后重算可用槽位并核对租约，不从队列长度推断已经消耗的资源。统计事件延迟时采用保守估算，避免重复启动导致超额。人工增加槽位需要平台运营工单。

监控包括队列等待、槽位使用、每日计算时长、抢占次数、租约失效和检查点恢复。软阈值告警只提示容量压力，硬阈值事件也不调用业务下游。查询按组织和队列隔离，用户只能查看自己有权限的任务，平台运营查看匿名化聚合。

测试覆盖时区边界、重复提交、抢占、取消、旧执行器和配额服务故障。文档中的组织、队列、每日时长、两分钟和三次抢占属于批任务调度，不得套用到在线写请求的用户项目配额或应用健康回滚。

## 资源核算与验收矩阵

资源核算以执行器实际租约时间和规格为基础，排队时间不计入计算时长。检查点写入期间仍占用槽位，任务暂停后释放计算资源但保留恢复元数据。异常退出按照最后心跳估算尾部用量，后续事件到达时通过更正记录调整。

验收用例覆盖组织刚好用完每日时长、关键队列预留空闲、普通队列借用容量、抢占后恢复、跨日运行和结算区域变更。每个用例检查队列状态、槽位、核算事件和用户响应。仅检查执行器数量不能证明公平性。

任务族防规避规则使用调用方声明和输入输出关系。拆分检测只影响调度优先级，不合并任务数据。误判可以由平台运营解除，并记录范围和到期时间。业务团队不能自行修改任务族标识来获得额外并发。

执行器启动成功但租约提交失败时立即自停，不运行用户代码。租约提交成功但启动响应丢失时，调度器查询执行器标识而不是再次创建。输出提交先写临时位置，摘要校验后原子发布，失败尝试不能覆盖成功结果。

权限测试区分任务提交、查看、取消、提高优先级和调整组织配额。项目管理员不能调整组织全局槽位，平台运营调整需要工单。查询结果按组织和队列过滤，日志中的输入参数执行脱敏。

上线检查包括队列权重、关键预留、每日窗口、检查点存储、租约时长和告警。配置修改从下一调度周期生效并携带版本。大规模调整先在模拟负载回放，确认不会让一个组织长期饥饿。

成本预估在提交时展示，但最终核算以实际执行为准。预估超过组织预算时要求负责人确认，不等同于获得额外槽位。取消任务只停止未来消耗，已经使用的资源仍进入账单。

输入数据权限在任务启动和每次恢复时重新校验。权限撤销后不再读取新分片，已经生成的输出转入隔离。调度器不能因为任务已有检查点就忽略最新权限。

跨区域队列根据数据驻留和容量选择执行位置。任务不能为了更快获得槽位把受限输入搬到未批准区域。区域容量不足时保持排队并返回原因，除非任务定义预先允许其他区域。

任务镜像和依赖绑定不可变摘要。摘要被安全隔离后，新尝试停止启动；正在运行任务由安全策略决定终止或完成检查点。更换镜像产生新尝试版本，不覆盖原执行证据。

治理报表按组织展示长期排队、反复失败、无所有者和高成本任务族。报表建议调整队列或优化任务，但不会自动提高优先级。长期无所有者任务暂停新尝试，已有输出仍按原生命周期处理。

队列下线前迁移排队任务并等待运行租约结束。强制下线需要平台工单，任务状态明确记录迁移或取消原因。

# 通知发送速率与抑制规则

## 消息分类和发送窗口

通知平台处理邮件、短信、站内信和推送。限额按接收人、通知类别和渠道计算，不按项目写操作配额计算。安全告警、账单提醒和营销消息使用不同策略，不能共享剩余额度。服务端接收时间决定窗口，调用方时间只作为消息内容。

发送请求必须包含模板、接收人、类别、渠道、语言和幂等键。平台先校验模板版本与接收同意，再进入频率判断。相同幂等键重复提交返回原消息标识，不再次占用额度。模板参数缺失或包含禁止字段时直接拒绝，不进入下游供应商。

普通产品通知每个接收人每小时最多二十条，每天最多一百条。达到小时软阈值时，低优先级消息进入摘要队列，高优先级消息继续发送；达到日硬阈值时，除安全类外全部抑制。安全告警单独使用五分钟去重窗口，不受营销额度影响。

抑制响应包含原因、策略版本和预计恢复时间。被抑制消息不会调用供应商，也不会自动在窗口恢复时补发，除非业务明确选择摘要模式。摘要任务合并同类别消息并使用新的幂等键。调用方不得循环更换模板规避接收人限额。

退订状态优先于频率配额。接收人退订某类别后，该类别立即停止，已经交给供应商的消息尽力取消。安全和交易必要通知按照法律基础独立处理，但必须使用明确类别。跨渠道退订按配置传播，不能把短信退订自动解释为所有站内信退订。

## 供应商故障、恢复与审计

供应商超时进入重试队列，重试不重复占用接收人额度。响应明确失败时按照渠道策略切换备用供应商，切换次数受限。未知状态先查询供应商结果，不能立即重发造成重复通知。供应商请求和响应中的敏感字段在日志中脱敏。

通知平台恢复时先加载幂等记录、额度计数和抑制状态，再消费积压消息。计数快照与事件日志按版本合并，旧事件不能减少已经使用的额度。若计数存储不可用，营销消息拒绝发送，安全告警采用严格本地上限并记录降级。

审计事件包括接收、模板校验、额度判断、抑制、供应商尝试、送达、退订和摘要生成。查询至少限定组织和通知类别。业务团队只能看到自己模板的记录，平台运营查看跨组织供应商指标时不展示接收人。导出遵循通知域的数据期限。

监控包括发送量、软阈值摘要、硬抑制、供应商延迟、重复率和退订传播。容量告警不自动提高接收人上限，策略修改需要通知治理负责人批准。配置发布绑定版本和生效时间，回退配置不会补发历史抑制消息。

测试使用虚构接收人和模拟供应商，验证小时与日边界、渠道隔离、幂等、退订、未知状态和恢复计数。二十条、一百条和五分钟是通知域参数，不能替代在线写配额的用户项目维度、批任务并发槽位或发布回滚条件。

## 模板治理与验收要求

模板发布包含版本、类别、渠道、参数模式、语言和合规声明。修改类别或新增敏感参数需要治理审核。发送请求绑定模板版本，模板之后更新不会改变已经排队的消息。下线模板阻止新请求，但允许已交给供应商的消息完成。

验收用例覆盖小时最后一秒、日切换、同一接收人多渠道、退订与发送并发、供应商未知状态、摘要合并和模板下线。每个用例检查额度计数、抑制原因、供应商调用和审计事件。只看最终送达会掩盖重复调用。

额度计数采用分片存储和服务端窗口标识。分片合并延迟时使用保守本地上限，不能因为暂时看不到其他分片就超发。计数事件重复按消息标识去重，迟到事件仍归属原窗口，不修改当前窗口恢复时间。

供应商切换保持同一消息标识并增加尝试编号。备用供应商返回成功后，主供应商迟到成功会被识别为潜在重复并告警。对于不能撤回的渠道，平台不再发送第三次补偿。业务方看到统一状态和尝试摘要。

权限测试区分模板编辑、模板批准、消息查询、重发和策略管理。重发动作重新经过当前退订与额度判断，不能绕过限制。支持人员跨组织查看需要工单，接收人地址默认掩码。导出不包含模板中的秘密参数。

上线检查包括策略版本、窗口时钟、供应商凭据、退订传播、摘要队列和告警。提高上限前使用历史负载评估用户影响。紧急降低上限立即作用于新请求，但不会撤回已经送达消息，变更记录明确生效时间。

多语言模板缺少目标语言时按照类别选择回退语言，营销消息没有批准回退模板则抑制。回退不改变额度类别。字符集或长度超过渠道限制时在调用供应商前失败，不能静默截断关键交易内容。

送达回执乱序时按尝试编号和供应商时间合并，最终状态不能从已送达退回到发送中。用户投诉关联具体消息和模板版本，治理人员据此调整策略而不是直接删除审计记录。

跨区域发送按照接收人地区选择合规供应商和允许时段。地区无法确定时采用更严格策略，不从语言猜测位置。区域切换不重置接收人额度，同一窗口的计数通过全局消息标识合并。

静默时段内低优先级消息延后到允许时间，高优先级交易消息按策略发送。延后消息在真正发送前重新检查退订、模板和额度，不能沿用排队时结论。

治理报表展示高投诉模板、长期抑制、异常重试和无所有者模板。下线建议需要模板负责人确认，紧急安全隔离可以立即阻止新发送，但不能删除历史送达与退订证据。

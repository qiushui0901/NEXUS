# 临时访问授权与到期回收

## 临时授权的创建与传播

临时访问用于短期排障、客户协助或跨团队联调，不等同于永久成员权限。申请必须包含目标项目、角色、原因、工单、开始时间和结束时间。结束时间最长不超过七天，生产管理权限最长不超过八小时。系统以服务端时间判断授权窗口，客户端时钟只用于显示，不能延长授权。

普通只读访问由项目负责人批准；可写访问还需要资源所有者确认；生产管理权限需要值班负责人和安全负责人共同批准。批准结论绑定角色和资源范围，申请人修改任一项都会重开审核。延长到期时间视为新授权，不沿用原批准。等待审批超过三十分钟时提醒当前处理人，超过两小时升级给值班负责人，但不自动授予权限。

授权开始时，权限服务发布临时授权事件，各业务服务在十分钟内刷新本地策略缓存。刷新期间旧策略可能仍看不到新权限，因此前端应展示“传播中”，而不是反复提交申请。传播失败会进入重试队列并产生告警。临时授权的十分钟传播目标与永久权限撤销的时限不同，不能混用。

到期时先阻止创建新会话和新任务，再等待正在执行的只读请求自然完成。现有交互会话最多继续两分钟，后台写任务立即取消。权限服务发布到期回收事件，并在十五分钟内核对所有消费者确认。未确认的消费者会被隔离并强制刷新。这里的两分钟不是账号冻结后的会话保留规则。

项目负责人可以提前结束临时授权。提前结束只影响目标项目和指定角色，不改变用户在其他项目的永久身份。若用户同时拥有永久角色，系统计算剩余有效权限，不能简单把全部权限清空。回收结果按资源逐项记录，便于解释为什么某些访问仍然有效。

## 续期、异常与恢复

续期必须在当前授权到期前提交，包含新的结束时间和继续访问的理由。审核未完成时，原授权仍按原时间到期，不提供宽限期。紧急事故中可以创建最多一小时的应急授权，由值班负责人即时批准，安全负责人需要在事故结束后复核。应急授权不能连续续期，也不能转换为永久成员。

授权数据包含申请、批准、传播、消费者确认、到期和回收状态。状态机只允许从待审进入已批准或已拒绝，从已批准进入传播中，再进入有效、回收中和已结束。消息重复不会让已结束授权重新生效。任何人工修复都必须比较当前状态版本，避免旧事件覆盖新的回收结果。

缓存恢复时先加载有效授权快照，再回放快照之后的事件。快照生成时间早于授权结束时间并不意味着授权仍有效，恢复程序必须重新按服务端当前时间计算。若事件存储不可用，系统采取拒绝优先策略，暂停创建新的临时授权；已有永久权限继续由正常策略判断。

审计查询至少按用户、项目和时间范围过滤。查看临时授权审计不代表可以修改授权。导出文件的有效期由安全审计域控制，不能从授权时长推导。监控包括待审数量、传播延迟、到期回收延迟、消费者未确认数和应急授权数量。告警只触发人工检查，不会自动延长访问。

测试场景覆盖角色叠加、跨项目隔离、到期边界、服务端与客户端时钟偏差、重复事件和缓存重建。测试账号使用虚构项目，不记录真实用户信息。文档中的七天、八小时、十分钟、两分钟和十五分钟只属于临时授权流程，不能替代永久撤销或账号冻结政策。

## 消费者契约与验收清单

每个权限消费者必须上报最后应用的策略版本、刷新时间和项目范围。确认消息只说明本地策略已更新，不代表用户已经建立会话。权限服务根据消费者注册表判断传播完成，临时离线消费者会标记为隔离，恢复后先拉取全量快照再接收增量。

验收用例覆盖开始时间在未来、结束时间刚好等于当前时间、永久角色与临时角色重叠、提前结束后迟到的批准事件、项目被删除以及组织目录中的用户停用。每个用例检查最终有效权限集合，而不是简单断言临时记录已结束。跨项目结果必须逐项比较。

审批回调重复或乱序时，状态版本较新的结果优先。驳回事件不能覆盖已经到期的记录，旧的传播确认不能让回收状态回到有效。数据库提交成功但事件发布失败时，事务外盒继续补发；补发使用相同事件编号，消费者必须幂等。

权限查询接口返回生效来源，区分永久角色、临时授权、应急授权和组织继承。前端撤销按钮只针对可撤销来源，不能误导管理员清除继承权限。审计导出使用稳定授权编号，不包含访问令牌或会话内容。

安全测试尝试延长客户端时间、修改项目标识、复用批准签名、让申请人与批准人相同以及通过旧缓存继续写入。性能测试模拟大量授权同时到期，确认回收队列有界且关键项目优先。故障测试让一个消费者长期不确认，验证隔离而不是无限重试。

上线检查包括服务端时钟同步、消费者清单、隔离开关、应急角色范围和告警路由。新增消费者必须先通过快照与增量一致性测试。修改最大时长只影响新申请，现有授权不会被静默延长；缩短规则是否立即生效需要单独迁移计划。

治理报表每周列出即将到期、传播超时、长期未确认和频繁申请的授权。负责人需要逐项确认是否仍有业务理由。报表只提供调查线索，不自动撤销尚未到期的合法授权，也不把临时访问转换成永久成员。

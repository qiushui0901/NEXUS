# 采购订单审批与生效规则

## 采购申请的审核路径

采购申请进入待审状态后，由申请部门负责人先核对预算科目、成本中心、供应商范围和交付日期。普通采购只需要一名部门负责人确认，金额超过部门月度阈值时才追加财务复核。系统不得因为等待时间过长而改变审批结论；等待八小时后发送一次提醒，等待二十四小时后升级给采购运营，但申请仍保持待审。提醒对象包括当前处理人和申请人，不向其他部门广播。

采购审批关注的是订单预算，不等同于产品发布审批。审核人看到的是申请快照、报价单摘要、税率、币种和交付计划。申请人在审核期间修改金额、供应商或成本中心时，旧审核自动作废，系统创建新的审批实例。只修改备注或联系人不会重开流程，但必须记录差异。已经驳回的采购申请可以复制为新申请，新申请拥有新的编号和审核链，不沿用旧申请的批准记录。

紧急采购允许缩短提醒间隔，但不能跳过预算检查。生产事故所需物料可以先由值班采购确认，再在两个工作日内补齐财务复核；补审失败时停止后续采购，不撤销已经签收的物料。紧急标记、事故编号、处理人和补审期限必须写入审计事件。系统不允许申请人同时担任最终批准人，也不允许通过批量接口绕过职责分离。

审批完成后，订单服务校验批准金额不小于最终订单金额、币种一致、供应商仍在可用名单内。批准记录绑定采购申请版本，而不是绑定页面上最后一次展示的文本。生成订单时必须重新读取预算余额，余额不足则返回业务冲突并保留原批准记录，不能自动改用其他成本中心。订单创建成功后发布采购事件，库存、财务和通知服务各自消费。

撤回操作只允许在订单尚未生成时执行。撤回后申请回到草稿，原审批实例关闭；再次提交会形成新的审核轮次。采购运营可以取消异常申请，但必须填写原因和关联工单。对于重复提交，系统按照申请内容摘要和幂等键识别，不得因为审批人相同就合并两个不同申请。查询接口按组织和成本中心过滤，避免跨部门看到报价信息。

## 订单变更、关闭与审计

订单生效后的数量或交付日期调整走订单变更单，不回到产品发布流程。变更金额上升时重新执行预算审批，金额下降时只记录财务确认。更换供应商始终需要采购运营复核，即使总金额没有变化。系统保留原订单、变更单和每次批准快照之间的引用，前端不得覆盖历史版本。

订单关闭分为正常完成、供应商取消和内部终止。正常完成要求所有收货记录已确认；供应商取消要求上传通知证据；内部终止需要部门负责人说明未使用预算的释放方式。关闭动作不会删除审批记录，审计在线保存周期遵循采购账务政策。导出采购记录时使用一次性下载地址，地址有效期与安全审计导出不同，由采购域单独配置。

故障恢复时，以订单数据库中的最终状态为准，不根据消息队列重放次数重新批准。若订单事件发送失败，事务外盒会重试，消费者依靠订单编号和事件序号去重。恢复任务只能补发已提交事件，不能补造批准记录。任何人工修正都要记录操作人、原因、前后值和工单号，并在下一次对账中展示。

监控指标包括待审时长、升级提醒数、预算冲突、变更单数量和事件补发次数。告警只说明流程可能阻塞，不会触发自动批准。压测数据使用虚构供应商和成本中心，不得混入真实报价。文档中的八小时、二十四小时和两个工作日是采购域规则，不能用于需求发布、账号冻结、日志保留或回滚判定。

## 验收场景与职责边界

验收用例需要覆盖预算刚好等于阈值、超过阈值一个最小货币单位、币种修改、供应商停用、报价过期和交付日期跨月。每个场景同时断言申请状态、审批实例版本、预算占用和审计事件，不能只看页面按钮是否可用。并发提交时只有一个申请版本能够进入待审，落后的请求收到当前版本并提示重新加载。

审批人离职或休假时，由组织目录提供有效代理关系。代理只在明确时间窗口内生效，不能继承审批人的其他项目权限。代理完成审核后，记录实际操作者和被代理人。代理关系到期不会撤销已经完成的结论，但未处理任务重新分配。组织目录不可用时暂停新增代理，已有待审任务保持原处理人。

预算服务短暂不可用时，申请可以保存草稿但不能提交审核。审核阶段预算查询失败会保持待审并显示依赖异常，不把未知状态解释为预算充足。订单创建阶段失败可以重试同一幂等键，重复成功响应返回已有订单号。跨服务补偿只释放本申请的预算预留，不影响同成本中心其他订单。

报表分别展示申请金额、批准上限、最终订单金额和后续变更，不用一个“金额”字段覆盖所有语义。财务对账按订单和变更单重建累计占用，发现差异时生成异常项，不直接修改审批记录。审计人员可以查看流程和摘要，但报价附件仍受采购权限控制。

安全测试验证申请人伪造成本中心、审批人越权访问其他部门、重复回调、过期代理和批量接口绕过。性能测试确保大批待审任务不会改变顺序或丢失提醒。恢复测试在批准后、订单创建前中断，确认重启后不会再次扣减预算，也不会因为检测到批准记录就跳过供应商复核。

上线检查包括配置阈值、组织目录连接、预算服务幂等、事件消费者版本和告警路由。任何阈值调整都要记录生效时间，只影响之后提交的申请。历史申请继续使用提交时策略版本，避免同一审核轮次在重放时得到不同路线。

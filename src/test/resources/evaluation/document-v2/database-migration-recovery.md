# 数据库迁移执行与补偿恢复

## 迁移计划和执行窗口

数据库迁移包括结构变更、数据回填和索引调整，与应用制品自动回滚是不同流程。迁移计划必须列出受影响表、容量估算、锁风险、兼容窗口、校验查询、停止条件和补偿步骤。高风险迁移需要数据库负责人和业务负责人共同确认，普通在线索引由数据库负责人批准。

迁移采用向前兼容顺序：先增加可空字段或新表，再部署双读双写代码，完成回填和校验后切换读取，最后在独立窗口清理旧结构。应用版本不能先依赖尚未创建的字段。每个阶段有独立执行编号和状态，失败后只重试当前阶段，不重复已经提交的步骤。

结构变更前记录模式摘要、数据库版本、执行参数和受影响对象。该摘要用于核对，不等同于应用制品摘要。数据回填按照主键范围分批，每批最多运行五分钟，批次之间检查复制延迟和错误率。客户端时间不参与游标推进，恢复从最后确认的主键继续。

停止条件包括锁等待超过三十秒、复制延迟超过五分钟、错误率连续两个批次越界或校验差异超过阈值。触发停止时暂停新批次，不自动执行反向 DDL。值班人员先判断已提交范围，再选择继续、补偿或保持兼容状态。停止次数不是应用健康检查的回滚次数。

不可逆迁移必须先完成备份验证和演练，并提供业务补偿方案。备份存在不代表可以无损回退，因为迁移期间可能产生新业务数据。任何恢复动作都要保护迁移后写入的数据，不能简单覆盖整个数据库。涉及删除字段时至少保留一个完整发布周期。

## 补偿、校验与事件记录

补偿优先使用向前修复，例如新增修正字段、恢复兼容视图或重新回填。只有尚未承载新数据的结构变更才允许执行反向 DDL。数据补偿按事件或主键范围生成，先在影子表校验，再合并到正式表。补偿脚本同样需要版本、摘要和审批。

迁移完成条件包括结构一致、回填数量一致、抽样内容一致、复制延迟恢复和应用护栏正常。校验结果写入迁移记录，不能只保存在终端日志。抽样失败会阻止关闭迁移，但不自动删除已写入数据。关闭后仍保留观察窗口和快速诊断查询。

迁移编排服务恢复时读取数据库锁表和迁移状态表，不从消息队列最后一条通知推断结果。状态版本防止旧执行器继续推进。重复启动同一执行编号返回当前状态，新的计划必须使用新编号。人工修改状态表被禁止，紧急修正需要审计工单和双人操作。

审计事件包含计划批准、阶段开始、批次推进、停止触发、补偿、校验和关闭。查询按项目、数据库和执行编号过滤。监控包括锁等待、复制延迟、批次耗时、校验差异和补偿积压。告警只暂停或通知，不会自动批准不可逆操作。

测试使用合成表和隔离数据库，覆盖断点续传、重复批次、复制延迟、旧执行器、补偿与新数据保护。五分钟批次、三十秒锁等待和连续两个批次是数据库迁移参数。它们不得替代应用发布的三次健康检查、功能开关观察窗口或配额限制。

## 兼容性验证与验收清单

迁移前对当前应用版本、下一应用版本和回退应用版本分别执行兼容性检查。新增字段必须允许旧版本忽略，新写入格式必须能被过渡读取器解析。清理旧结构前确认所有运行实例、离线任务和报表都已迁移，不能只检查在线服务。

验收用例覆盖空表、大表、热点主键、长事务、只读副本延迟、批次重复和应用在迁移中滚动重启。每个用例记录结构摘要、行数、校验结果和复制位置。只看到迁移任务成功状态不足以证明业务读取兼容。

分布式锁租约包含数据库、计划编号和阶段。执行器必须在每批提交前确认租约，租约丢失后立即停止。新执行器接管时读取最后提交批次和校验状态，不重复未确认的外部副作用。锁服务不可用时不启动新阶段。

备份验证包括可读取、摘要一致、恢复时间和权限隔离。演练备份使用隔离实例，不覆盖正式环境。备份超过计划允许年龄时阻止不可逆步骤。恢复演练成功不等于生产可直接全库覆盖，事故方案仍需评估迁移后新增数据。

权限测试确保计划创建者、批准人、执行人和数据库管理员职责分离。只读观察者可以查看摘要与进度，不能下载包含业务数据的样本。紧急操作要求双人确认和事故编号，自动化令牌限制到明确数据库和时间窗口。

上线前检查连接池、锁超时、复制告警、校验查询成本、补偿脚本和通讯计划。迁移参数调整形成新计划版本。已经开始的计划保持原批次大小，除非暂停并通过显式变更审核，避免恢复时使用不一致参数。

容量评估同时计算临时索引、双写日志、备份和回填工作表空间。剩余空间低于安全阈值时不开始新阶段。扩容完成后重新采集估算，不能沿用几天前的容量快照。

业务校验由领域负责人提供稳定查询和容差。查询脚本版本随迁移计划冻结，临时修改必须留下差异。技术行数一致不代表业务金额、状态或关联关系正确。

多区域数据库按复制拓扑安排迁移顺序。只读区域先验证兼容性，主写区域在明确窗口执行，灾备区域确认日志可重放后才关闭计划。任何区域失败都会暂停后续步骤，但不会自动对已成功区域执行反向变更。

迁移通讯包括开始、阶段完成、暂停、补偿和关闭。消息只是状态展示，真实结果来自迁移状态表和数据库校验。通知丢失不会触发重复执行。

03 · TECHNOLOGY CHOICES

选型围绕边界，不围绕热度

每个组件承担一种明确的数据语义，避免用一个数据库或一个模型包办所有问题。

问题选择为什么
企业 Java 服务Java 17 + Spring Boot 3.4.9

稳定运行时、成熟 Web/Validation/Actuator 体系；JDK 与内部平台基线一致。

模型接入Spring AI 1.1.2 + OpenAI Compatible

生成、嵌入和工具协议解耦；模型按任务路由，不绑定单一供应商。

语义召回Qdrant named vectors + sparse

同一 point 同时承载原始语义、业务描述和关键词信号，原生过滤项目与版本。

代码结构Tree-sitter + SQLite

Tree-sitter 统一多语言抽取；SQLite 用事务保存可审计的 commit 级调用图，无需引入图数据库。

文档解析Apache Tika + 专用 ZIP/XLSX Loader

通用格式交给成熟解析器，业务结构保留专用规则，避免统一成失真的纯文本。

Agent 接入MCP Streamable HTTP

不自建 IDE；把内部证据开放给现有 Agent 客户端，复用开发者已有工作流。

前端交付静态 HTML + Vue WebJar

管理与浏览页面随单个 JAR 发布，无 Node 构建链；当前规模下维护成本最低。

04 · RETRIEVAL & RELIABILITY

不是一次向量查询，而是一条可诊断管线

Route

意图与画像

需求评审、代码定位或混合开发问题，选择最小检索策略。

Recall

多路并行召回

需求 dense/sparse，代码正文/业务描述/sparse，受控线程池并发。

Rank

融合与重排

RRF 合并多路排名，LLM 重排可配置，保留混合顺序兜底。

Reflect

证据反思

检查命中阈值、唯一父块和双侧覆盖；不足时最多补检一次。

Deliver

结构化交付

返回证据、质量、阶段诊断与稳定 warning code。

07 · ADVANTAGE & STRATEGY

优势来自组合，
壁垒来自数据契约

POSITIONING
研发 Agent 的
版本化证据基础设施

上接 Copilot、Cursor、Claude Code、TRAE 等 Agent；下接内部需求、代码、测试、Wiki 与版本事实。

01 · 先做深证据链

强化需求 → 代码 → 调用影响 → 测试的显式关联，而不是增加聊天入口。

02 · 再做质量闭环

固定黄金集、污染率、引用合法率和 P95；模型与参数变更必须过门禁。

03 · 保持可替换

模型供应商、Embedding、Agent 客户端和存储实现均不成为业务事实的唯一宿主。

04 · 不扩张执行面

不自建 AI IDE，不与成熟 Agent 争夺代码执行；通过 MCP 放大已有知识资产。

一句话总结：通用 Agent 负责“做事”，NEXUS 负责告诉它“基于哪个版本、哪些证据、影响到哪里”。

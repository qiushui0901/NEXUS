# 企业级代码 RAG 代码标注（Code Annotation）完整设计方案

版本：V1.0

------------------------------------------------------------------------

# 1. 背景

传统代码搜索主要依赖：

-   文件名搜索
-   关键词搜索
-   IDE索引

例如：

用户输入：

    支付失败重试逻辑在哪里？

传统搜索只能匹配：

    payment
    retry
    fail

但是企业代码存在大量问题：

-   中文需求和英文代码不匹配
-   业务含义隐藏在代码中
-   类名和方法名无法表达完整业务
-   调用关系无法通过文本搜索发现
-   一个问题涉及多个服务

因此需要建设：

    代码
    +
    结构知识
    +
    业务知识
    +
    调用关系
    +
    风险知识

形成代码知识库。

------------------------------------------------------------------------

# 2. 代码标注目标

代码标注的核心目标：

## 2.1 提升代码检索能力

实现：

    自然语言需求

    ↓

    代码定位

    ↓

    相关类/方法

例如：

用户：

    订单支付失败如何处理？

能够找到：

    PaymentService.pay()

    PaymentRetryService.retry()

    PaymentExceptionHandler.handle()

------------------------------------------------------------------------

## 2.2 支撑代码理解

回答：

-   这个类负责什么？
-   为什么调用这个方法？
-   上下游是什么？
-   修改会影响什么？

------------------------------------------------------------------------

## 2.3 支撑研发智能Agent

支持：

-   需求分析Agent
-   Code Review Agent
-   Bug分析Agent
-   链路分析Agent
-   测试生成Agent

# 5. 文件级标注

## 5.1 标注内容

``` json
{
"file_name":"PaymentService.java",
"language":"Java",
"module":"payment-service",
"path":"xxx/payment/service",
"layer":"service"
}
```

## 5.2 来源

自动获取：

-   文件路径
-   package
-   Git信息
-   项目结构

------------------------------------------------------------------------

# 6. 模块级标注

企业项目：

"支付中心",

# 7. 类级标注

## 7.1 基础信息

例如：

``` java
@Service
public class PaymentService
```

生成：

``` json
{
"class_name":"PaymentService",

"type":"Service",

"annotation":[
"Service"
],

"package":
"com.xxx.payment"
}
```

------------------------------------------------------------------------

## 7.2 类职责分析

LLM生成：

``` json
{

"负责订单支付核心流程",

"business_domain":
"交易支付",

"keywords":[
"支付",
"扣款",
"交易"
]
}
```

# 8. 方法级标注

方法是代码RAG最重要的检索单位。

例如：

``` java
public PayResult pay(Order order)
```

生成：

``` json
{
"method":"pay",

"input":[
"Order"
],

"output":
"PayResult",

"type":
"business_method"
}
```

------------------------------------------------------------------------

# 9. 调用关系标注

代码理解不能只依赖向量。

需要构建：

    调用图(Call Graph)

例如：

    OrderController

            |
            v

    OrderService

            |
            v

    PaymentService

            |
            v

    PaymentGateway

Metadata：

``` json
{
"caller":
"OrderService.createOrder",

"callee":
"PaymentService.pay"
}
```

用途：

-   影响分析
-   链路分析
-   Bug定位

------------------------------------------------------------------------

# 12. 业务语义标注

这是代码RAG效果提升最大的部分。

静态分析无法知道：

    PaymentService.pay()

真正含义：

    处理订单支付

    调用第三方支付渠道

    失败后支持重试

    涉及资金一致性

因此使用LLM。

------------------------------------------------------------------------

# 18. 代码切片策略

错误：

    整个Java文件一个chunk

原因：

-   太长
-   语义混乱
-   检索精度低

推荐：

    Class

      |

    Method

      |

    Business Flow

------------------------------------------------------------------------

# 19. 推荐Chunk结构

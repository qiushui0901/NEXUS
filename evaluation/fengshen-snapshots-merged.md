福利-成长基金
成长基金系统策划案（礼包商城页签版）
文档目标：形成可直接进入评审/开发的系统策划口径。
适用端：手机端竖屏界面（参考比例 9:19.5）。
系统形态：礼包商城内页签玩法，成长基金为独立页签。
一、系统定位
成长基金是礼包商城中的长期付费养成返利玩法：
• 玩家一次付费激活成长基金。
• 随主角等级达成对应档位，领取该档灵玉奖励。
• 支持对已达成但未领取档位进行补领。
本系统奖励仅有一种货币：灵玉。
二、入口与页面结构
2.1 入口链路
主界面 → 礼包商城 → 成长基金页签
2.2 页面结构（自上而下）
1. 顶栏：返回按钮 + 标题“礼包商城”。
2. 页签栏：周卡 / 至尊特权 / 成长基金 / 礼包合集（成长基金高亮）。
3. 基金宣传区：
o 标题“成长基金”
o 宣传文案“10倍返利 XXXX 灵玉等你来拿”
o 购买按钮（含价格）
o 累计收益文案“累计可获得 XXXX 灵玉”
4. 成长档位列表（纵向）：每行一个等级档位。
三、核心规则
3.1 激活规则
• 成长基金仅可通过付费购买激活。
• 支付成功后将 fund_activated 置为 true。
• 已激活状态可长期生效（活动型可由配置时间窗控制）。
3.2 领取规则
档位 m 可领取当且仅当：
• role_level >= need_level(m)
• claimed[m] = false
• 若为基金奖励（本系统全部为基金奖励），需 fund_activated = true
3.3 补领规则
• 已达成但未领取的历史档位，在激活后可逐档领取。
• 可选支持一键领取（若实现一键，后端需幂等）。
3.4 奖励规则
• 奖励类型固定为灵玉，不混入其他道具。
• 每档展示灵玉数量文本（如 2000 灵玉）。
• 每档同时展示灵玉图标组，越靠后档位图标数量越多（视觉价值递增）。
四、档位行 UI 规范
每个档位行包含：
1. 左侧：灵玉图标区域（静态图标组）。
2. 中间：
o 等级文案：等级达到:X
o 数量文案：N 灵玉
3. 右侧：状态按钮（3态）及可领奖励红点（见红点规则）。
4.1 按钮三态定义
1. 未达标：灰色按钮，文案“未达标”，不可点击。
2. 可领取：
o 已购买：绿色领取按钮。
o 未购买：蓝色领取按钮（与已购买可领区分）。
3. 已领取：灰蓝按钮，文案“已领取”，不可点击。
五、红点规则
5.1 档位红点
当 role_level >= need_level(m) 且 claimed[m] = false 时，档位显示红点。
该规则与是否已购买无关（未购买但已达标同样显示红点）。
5.2 页签红点
成长基金页签红点与“是否存在任一可领奖励档位”一致。
进入页面刷新后，清除页签红点。

八、交互流程
flowchart TD
Entry[进入礼包商城] --> Tab[切到成长基金页签]
Tab --> Load[拉取配置与玩家状态]
Load --> Ready{是否达成档位}
Ready -->|否| ShowNot[显示未达标]
Ready -->|是| ShowReady[显示可领状态+红点]
ShowReady --> BuyCheck{已购买?}
BuyCheck -->|否| Buy[点击购买]
Buy --> PayOK[支付成功]
PayOK --> Refresh[刷新状态]
BuyCheck -->|是| Claim[点击领取]
Claim --> Grant[发放灵玉]
Grant --> Mark[标记已领取]
Mark --> Refresh
九、接口建议

o 入参：fund_id

o 出参：是否激活成功
3. POST /growth-fund/claim

十一、边界与防御
场景 处理策略
重复点击领取 客户端按钮loading防抖 + 服务端幂等
支付成功未刷新 支付回调后强制刷新成长基金状态
升级后状态未刷新 监听等级变化事件并刷新档位状态
活动过期 end_time 后关闭购买/领取入口并展示结束态
已达标未购买点击领取 按规则拦截，提示先购买（按钮仍保留“可领取”样式）
十二、验收清单（提测口径）
1. 仅付费激活后可实际领取灵玉。
2. 领取按钮三态展示正确（未达标/可领取/已领取）。
3. 未购买但达标时，可领取按钮颜色与已购买可领取明显区分。
4. 达标未领时档位红点出现，且与购买状态无关。
5. 宣传区累计灵玉与档位总和一致。
6. 灵玉图标数量随档位递增。

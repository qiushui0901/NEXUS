# 需求增量继承与显式删除

## Goal

修正需求版本链语义：每个版本需求文档默认是增量记录，历史需求在新版本未出现时继续有效，只有结构化的显式删除操作才会从后续版本完整需求视图中移除。

## Requirements

- 需求快照必须按 `baseRequirementVersion` 递归合成完整版本视图。
- 当前版本未出现的历史需求必须继承，不得判定为删除。
- 同一需求再次出现时按稳定 `entryId` 更新；内容变化计为修改，内容相同不产生变化。
- 只有快照条目明确声明删除操作时才移除历史需求；不得根据正文中的“删除、取消、移除”等普通业务词推断。
- 旧快照未声明操作类型时必须向后兼容，默认视为新增或更新。
- 基线缺失、跨文档引用或继承环必须安全失败，不能返回伪造的完整需求差异。
- 无快照而回退到向量库时，条目缺席不得生成删除差异。
- 不提交向量、Qdrant 数据、原始大型产品文档压缩包或本地凭据。

## Acceptance Criteria

- [x] 比较相邻增量需求版本时，基线中未重复出现的条目仍存在于目标版本完整视图。
- [x] 比较 `5.0` 与 `5.1` 时不再因 `5.1` 文档较短而产生批量删除。
- [x] 同一 `entryId` 的新内容产生一条修改差异。
- [x] 显式 `REMOVE` 操作产生一条删除差异。
- [x] 正文包含删除类词语但未声明操作时仍作为正常需求处理。
- [x] 旧版快照 JSON 无需批量改写即可继续读取。
- [x] 缺失基线和继承环有自动化测试覆盖。
- [x] 完整 Java 21 测试与 `git diff --check` 通过。

## Notes

需求版本链记录的是业务需求的演进，不是每个版本互相独立的完整清单。完整视图由历史有效需求和当前版本增量合成。

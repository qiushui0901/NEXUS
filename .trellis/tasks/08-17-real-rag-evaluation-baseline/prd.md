# 真实 RAG 评测基线

## Goal

建立能够代表公司开发人员真实提问方式、可审计且可重复执行的需求、代码和联合检索评测基线，使检索相关改动能够用统一指标判断是否可发布。

## Background

- 现有 `RetrievalEvaluationIT` 已能执行真实检索链路并输出 JSON/Markdown 报告。
- 现有 `RetrievalQualityGateTest` 只证明冻结 Gold 不会被确定性流水线误删，不能证明真实依赖下的召回质量。
- 现有拾光 v1 数据集包含业务问法，但缺少结构化人工审核信息、语料 commit 和稳定证据 ID。
- 现有报告包含 Recall、MRR、无答案准确率和延迟，但缺少 nDCG 与整体降级率，也没有按阈值阻断真实评测。

## Requirements

### R1. 可信数据契约

- 新数据集使用显式 schema 版本，并保持旧 v1 数据集可加载。
- 每条 v2 用例必须记录项目、业务版本、固定语料 commit、问题类型和人工审核信息。
- 每个 Gold 必须具有稳定证据 ID；禁止使用 Qdrant point/vector ID。
- 人工审核状态必须为 `APPROVED`，并记录非空 reviewer 和 ISO-8601 审核时间。

### R2. 真实问题分布

- 问题不得主要依赖类名、方法名、完整路径等答案泄漏。
- 正式数据集覆盖业务语义、跨文档、多跳、历史版本、无答案和需求代码联合问题。
- 数据集至少包含 20 条互不重复的问题，并冻结 SHA-256。

### R3. 指标与报告

- 机器报告输出 Recall@10、MRR@10、nDCG@10、无答案准确率、降级率和 P95 延迟。
- 报告保留逐用例结果和失败归因，能够区分质量失败与基础设施失败。
- 同一用例有多个 Gold 时，nDCG 按实际相关项数量计算，不按“唯一相关项”近似。

### R4. 发布质量门

- 真实依赖评测支持读取版本化阈值文件。
- 低于 Recall/MRR/nDCG/无答案准确率下限，或高于降级率/P95 上限时，评测进程失败。
- 基础设施失败继续独立阻断，不得被质量指标掩盖。
- 默认 CI 不依赖 Qdrant、Embedding 或 BGE，但必须验证数据契约、冻结指纹、指标计算和质量门逻辑。

### R5. 可重复执行

- 提供单一脚本运行企业真实评测，参数通过环境变量传入，不包含本机绝对路径或密钥。
- 文档说明准备、执行、报告位置、阈值更新和人工审核流程。

## Acceptance Criteria

- [x] v2 数据集满足 R1/R2，测试锁定用例数、类型覆盖和 SHA-256。
- [x] 报告 JSON/Markdown 包含 R3 全部指标，并有单元测试验证计算口径。
- [x] 真实评测在配置阈值后执行 R4 门禁，任一指标越界时失败。
- [x] 默认 Maven 测试验证冻结数据集、门禁通过与门禁拒绝场景。
- [x] `tools/run-real-rag-evaluation.sh` 可重复调用现有 Maven 评测入口。
- [x] 简体中文使用文档说明 R5 全流程。

## Out Of Scope

- 不使用线上失败结果自动生成未经人工确认的 Gold。
- 本任务不自动抓取或脱敏公司私有仓库。
- 本任务不在普通 CI 中启动真实向量库、Embedding 或重排服务。
- 本任务不调整生产检索排序算法或阈值。

# GitLab 账号级项目发现与批量导入

## Goal

将 GitLab 接入入口从“逐仓库填写 Clone URL”改为“关联 GitLab 账号后发现项目”，让管理员能够查看该账号有权访问的项目，选择一个或多个项目导入 NEXUS，并继续使用现有同步、Webhook、代码索引与知识库能力。

## Background

- 当前 `GitLabSyncService.CreateProject` 一次只创建一个项目，并要求请求直接提供 `cloneUrl`、`branch`、`gitPath` 和 `accessToken`。
- 当前五步向导第一步要求填写单个 Clone URL 和 PAT，因此无法展示账号下的项目。
- PAT 当前按项目重复加密保存；账号级流程需要把 GitLab 连接凭据与导入后的项目记录分层。
- 既有 Git 操作已限制 HTTPS、Host 白名单、IP/内网地址，并使用受控 AskPass；这些安全边界必须保留。
- 已导入项目的同步队列、Webhook 幂等、动态项目注册和代码索引链路可以复用。

## Requirements

- 管理员可以创建一个 GitLab 账号连接，至少提供 GitLab 实例地址、显示名称和 Personal Access Token。
- 首版授权方式确定为 Personal Access Token，不实现 OAuth 跳转、回调或刷新令牌。
- 一个 NEXUS 实例支持多个命名 GitLab 账号连接；GitLab.com 与多个白名单内自建实例可以并存。
- 每个导入项目保存稳定的连接引用，账号连接之间的项目、凭据和错误状态不得串用。
- 后端通过 GitLab REST API 验证账号并读取该账号可见的项目，支持分页，不只返回第一页。
- 项目列表至少展示名称、`path_with_namespace`、可见性、默认分支、归档状态和最近活动时间。
- 管理员可以搜索、筛选并多选项目后批量导入。
- 项目发现范围只包含当前账号实际加入或拥有的项目（包括群组项目），不混入仅因公开可见而出现的无关仓库。
- 系统自动从 GitLab `path_with_namespace` 生成稳定 `projectId` 和 collection 名，默认端类型为服务端；导入前允许逐项目展开编辑。
- 批量导入提交成功后立即为每个项目启动首次同步和代码索引，并在现有任务时间线中展示进度。
- 批量导入按项目独立接受或失败，单个项目失败不得回滚其他已接受项目。
- 导入默认使用项目的默认分支；缺少默认分支的项目必须明确阻止并说明原因。
- 已导入项目在发现列表中显示状态，不允许无提示重复导入。
- 每个导入项目继续生成独立 NEXUS `projectId`、collection 和受控本地仓库路径。
- 新导入项目的 PAT 由连接记录统一加密保存，项目记录只引用连接，不复制凭据密文。
- PAT 不进入 URL、日志、公开错误、前端持久化或项目列表响应。
- GitLab API 请求必须复用现有 Host 白名单与私网地址限制，并设置有界连接/读取超时。
- 旧的已导入项目和现有同步、Webhook、重试、停用能力保持兼容。
- 账号连接失效时，已发布索引继续可读；同步任务明确失败并提示重新授权。
- `CHANGELOG.md` 在同一提交中记录该能力。

## Acceptance Criteria

- [ ] 关联账号成功后，可以看到该账号跨群组、跨命名空间有权访问的完整项目列表。
- [ ] 可以勾选多个项目并一次提交导入，导入结果逐项目返回成功或失败，不因单个项目失败丢失其他结果。
- [ ] 导入的项目进入现有 GitLab 项目列表，并可以执行首次同步、后续同步、重试和停用。
- [ ] 发现列表能区分未导入、已导入、不可导入和已归档项目。
- [ ] 新导入项目的 PAT 只在账号连接表中保留一份加密密文，API 和 UI 不回显；旧项目凭据保持兼容读取直到重新关联。
- [ ] GitLab.com 与配置白名单内的自建 GitLab 均可使用。
- [ ] 分页、Token 失效、403、429、超时、空项目列表和部分导入失败均有回归测试。
- [ ] 现有单项目记录可迁移或兼容读取，不要求用户重新建立全部索引。

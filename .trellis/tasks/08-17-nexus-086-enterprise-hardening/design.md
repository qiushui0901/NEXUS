# 技术设计

## 边界

企业化收口分为四条相互独立但按顺序交付的工作流：

1. 发布验证与工程治理：建立可信基线。
2. 真实 RAG 评测：建立可量化的产品质量门。
3. GitLab 自动接入：建立项目生命周期入口。
4. 多实例共享状态：消除单机状态依赖。

## 关键决策

- 保留 Qdrant 作为需求和代码向量存储。
- Git 仓库内容继续以具体 commit SHA 作为索引事实来源。
- GitLab Webhook 只提交受控任务，不直接在请求线程执行索引。
- 共享状态通过存储接口抽象逐步迁移；本地实现保留用于开发环境。
- 自进化策略继续默认关闭，只有验证报告和人工审批均通过后才能激活。

## 兼容与回滚

- 现有本地 profile 行为保持兼容。
- 新的共享后端和 GitLab 接入通过显式配置启用。
- 数据迁移采用先双读验证、再切换写入的方式。
- 任一阶段失败时均可退回当前单实例、本地仓库模式。

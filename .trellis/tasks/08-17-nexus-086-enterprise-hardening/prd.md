# NEXUS 0.8.6 企业化收口

## Goal

将 NEXUS 从功能完整的单实例内部试点系统，收口为可验证、可接入 GitLab、可供团队共享部署并可持续评测的研发知识 MCP 服务。

## Requirements

- 当前发布版本必须有与 HEAD、JDK 和测试结果绑定的机器可读验证报告。
- Trellis 任务、CHANGELOG、版本号和验证报告必须反映同一真实完成状态。
- 建立覆盖真实开发问题、无答案问题和需求/代码联合问题的 RAG 评测基线。
- GitLab 项目必须能够通过受控配置接入、同步并触发增量索引。
- 多实例部署时，索引任务、Wiki、策略和评测数据不得依赖实例本地状态产生不一致。
- 所有能力默认保持 fail-closed，并具备灰度启用和回滚路径。

## Acceptance Criteria

- [ ] `0.8.6` 当前 HEAD 的完整 Maven verify 报告可复现且进入版本库。
- [ ] 历史 Trellis 任务状态与已经发布的代码能力一致。
- [ ] 真实 RAG 评测集、指标和质量门可以在 CI 或受控环境重复执行。
- [ ] GitLab 项目接入支持鉴权、clone/fetch、Webhook、幂等增量索引与失败重试。
- [ ] 共享部署方案消除关键本地状态分叉，并记录迁移与回滚步骤。
- [ ] MCP 在共享部署环境下仍满足权限、证据和可观测性契约。

## Scope

- 本父任务由四个可独立验收的子任务组成。
- 本轮优先完成发布验证与工程治理，后续子任务按评测、GitLab、共享状态的顺序推进。
- 不把尚未完成的自动学习或多实例能力描述为线上已生效。

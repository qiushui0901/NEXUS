# 前端界面统一与体验改进

## Goal

按照 `docs/frontend-ui-consolidation-improvement-plan.md` 将 NEXUS 定义为统一的“知识与代码运营工作台”。首页、知识库、GitLab、Wiki 和代码工作台共享稳定的产品外壳、导航、项目上下文、状态语言和反馈方式，同时保留 Wiki 阅读体验与代码图谱的场景特征。

用户在任意页面都应能立即判断自己所在模块、当前项目/版本、系统状态和下一步操作，并能在桌面与移动端一次操作进入其他核心模块。

本任务与已经完成的 GitLab 可视化管理工作台共同组成 NEXUS `0.9.0` 发布范围。

## Background

- 五个核心页面分别演进，存在多套导航、色板、字体、圆角、间距、API Key 和错误提示实现。
- `knowledge.html` 与 `gitlab-settings.html` 已共享部分资产，但其他页面仍以内嵌 CSS/JavaScript 为主。
- `monitor.html` 约 2427 行，功能复杂且测试覆盖大量字符串契约，不适合一次性重写。
- 当前工作区包含上一任务尚未提交的知识库/GitLab 管理工作台实现，本任务必须在其基础上演进，不回退或覆盖这些改动。
- 部署继续使用 Spring Boot 静态资源、Vue 3 WebJar 和原生 JavaScript，不增加 npm 构建链或外部 CDN。
- 现有页面路由与后端 API 保持兼容，前端统一不能改变检索、索引、Wiki 生成和 GitLab 同步业务语义。

## Requirements

### R1 共享视觉基础

- 新增设计 Token，统一画布、表面、文本、状态色、字号、间距、边框、圆角、层级和焦点样式。
- 核心控件与状态文字不得小于 12px。
- 应用主体使用浅色运营工作台；整页深色只允许保留在代码图画布等明确场景区域。
- Wiki 正文标题可以保留衬线字体，导航、按钮、输入和管理界面统一使用无衬线字体。

### R2 统一应用外壳与项目上下文

- 五个核心页面共享品牌、完整一级导航、当前页面状态、项目上下文、系统状态入口和设置入口。
- 移动端通过菜单抽屉展示全部一级导航，不得使用 `display:none` 丢弃核心入口。
- API Key 从各页面头部移入统一“连接设置”弹层，兼容现有 `nexusApiKey` 本地存储键。
- 页面间导航尽可能保留 `projectId`、`version` 和相关上下文 query string。

### R3 统一错误、通知与加载反馈

- 新增错误规范化模块，清理 HTML 文档、堆栈、绝对路径、命令输出和内部异常细节。
- 页面初始化失败使用内容区错误状态；后台操作失败使用非遮挡通知；同一错误不得重复展示。
- 桌面通知位于顶部栏下方右侧，移动端位于底部安全区上方，最多同时显示两条并提供关闭或重试动作。
- 首次加载使用区域级加载/骨架；已有数据轮询刷新时不得清空列表或造成明显闪烁。
- 空状态必须说明原因并提供下一步操作。

### R4 首页运行总览

- 删除巨型 Hero 和高模块卡片，首页首屏改为运行总览。
- 展示项目、就绪、处理中、失败与服务健康摘要，并优先呈现需要处理的事项和快速操作。
- 模块入口由全局导航承担，不在正文重复展示营销式入口卡片。
- 运行状态接口不可用时页面仍可使用，并显示规范化错误与明确恢复动作。

### R5 知识库与 GitLab 管理体验

- 两页复用相同统计栏、筛选、表格/移动列表、状态标签、空状态、通知和抽屉组件。
- 知识库突出失败和处理中项；移动端将表格转换为结构化列表；重建等低频写操作进入操作菜单。
- 知识详情阶段栏可折叠，分块展示来源、摘要、向量/验证状态和可复制短 ID。
- GitLab 以统一版本状态表达 indexed/target commit 与 revision drift，失败项直接提供原因和重试。
- GitLab 向导区分普通/高级字段，连接测试显示检查清单，Secret 提供显示、复制与反馈，创建后原地展示首次同步状态。
- 停用等危险操作使用操作菜单和二次确认。

### R6 Wiki 与历史版本兼容

- Wiki 使用统一外壳并删除固定悬浮“管理知识库”入口。
- Wiki 保留“目录 / 正文 / 证据”信息架构；窄屏证据转为抽屉，移动端提供返回目录和查看证据操作。
- Wiki 继续保留现有 API、权限、空状态和深链行为。
- `/versions` 页面与版本比较 API 作为历史兼容能力保留，但不进入 0.9.0 核心导航、首页快捷操作或前端验收范围。

### R7 代码工作台

- 代码工作台整体使用浅色工作区；图谱通过低对比网格、节点边框和有限语义色区分，不使用大面积深色画布。
- 首屏核心控制重组为页面模式、查询输入和可折叠图谱选项三组。
- 高级筛选进入 Popover/抽屉，图例可折叠，自动识别使用开关。
- 右侧信息栏稳定为“信息 / 文件 / 证据”三项。
- 原始错误 HTML 必须经过统一错误规范化；通知最多两行，详情进入诊断区域。
- 390px 宽度下以“图谱 / 信息 / 文件 / 证据”全屏 Tab 切换，不同时展示图画布和侧栏。
- 迁移采用渐进拆分，保留现有图谱、开发方案、流式响应、源码抽屉和证据引用能力。

### R8 工程结构、兼容与文档

- 新增共享 CSS/JavaScript 资产，不引入 npm、打包器、外部 CDN 或大型 UI 框架。
- 保持 `/`、`/knowledge`、`/settings/gitlab`、`/wiki`、`/versions`、`/monitor` 及现有 API 路径不变。
- 更新页面契约测试、用户指南、手工冒烟文档和 `CHANGELOG.md` 当前版本。
- 不修改个人文件 `面试问答全解-NEXUS.md`。
- 不提交本地运行数据库、截图临时文件或其他运行时产物。

### R9 0.9.0 发布整合

- 将 Maven artifact、Spring 应用信息、README 当前版本和 Changelog 当前发布段统一为 `0.9.0`。
- `0.9.0` 同时包含 GitLab 自动接入/管理工作台、知识管理工作台和本次五个核心页面统一。
- 保留 `0.8.6` 真实 RAG 评测模式、阈值资源和历史验证报告名称；它们是基线标识，不随产品版本机械改名。
- 最终可执行产物必须为 `target/NEXUS-0.9.0.jar`。

## Out Of Scope

- 修改检索、索引、Wiki 生成、版本比较或 GitLab 同步核心业务逻辑。
- 引入 React/Vite/npm 或第三方 UI 框架。
- 改变认证模型、API Key 后端协议或现有权限规则。
- 一次性重写 `monitor.html` 的全部业务 JavaScript。
- 将 `tech-briefing.html` 强制改造成运营工作台布局；只要求统一品牌入口、Token 和焦点样式。

## Acceptance Criteria

- [ ] 五个核心页面加载共享设计 Token、应用外壳和组件资源。
- [ ] 任意页面均可一次操作进入其他四个核心模块，移动端不丢失一级导航。
- [ ] 页面间导航能保留可用的 `projectId`、`version` 上下文。
- [ ] API Key 仅通过统一连接设置维护，不再在多个页面头部重复显示输入框。
- [ ] HTML 错误、堆栈、绝对路径和命令输出不会直接呈现在通知或页面错误中。
- [ ] 首页首屏显示运行状态、待处理事项和快速操作，不再显示巨型 Hero/模块营销卡片。
- [ ] 知识库与 GitLab 在 390px 下使用结构化列表且无横向溢出。
- [ ] Wiki 无固定悬浮管理按钮，窄屏可返回目录并打开证据。
- [ ] 核心导航与首页不再出现版本比较入口，旧 `/versions` 页面与 API 仍可直接访问。
- [ ] 代码工作台首屏核心控制不超过三组，390px 下不同时显示图和详情侧栏。
- [ ] 代码工作台使用统一浅色工作区，核心文字不小于 12px。
- [ ] 所有状态同时使用图标、颜色和中文文本表达。
- [ ] `pom.xml`、应用信息、README、Changelog 与可执行 jar 均一致标识 `0.9.0`。
- [ ] 页面契约测试、JavaScript 语法检查、完整 Maven verify、`git diff --check` 和三组目标视口浏览器验收通过。

# 证据级引用与回答可信度校验

## Goal

让需求 RAG、代码 RAG 和 Wiki/开发方案中的生成结论都能回查到本次检索获得的真实证据，并由服务端判断引用是否有效、结论是否具备足够支持，避免模型伪造引用或把无依据内容展示成确定事实。

## Background

NEXUS 已统一需求与代码检索，并能识别需求、代码、测试和 Wiki 之间的结构化冲突；但开发方案的自然语言结论仍缺少细粒度证据绑定。同步接口与 SSE 页面目前只在末尾返回原始命中，无法说明某一条结论具体由哪些需求片段或代码符号支持，也无法识别模型输出的非法证据 ID。

## Requirements

### R1. 统一证据契约

- 定义统一的 `EvidenceRef`、证据类型、引用支持状态和引用质量摘要。
- 需求证据至少包含：稳定证据 ID、项目、文档版本、文件、父块标识、受限摘录。
- 代码证据至少包含：稳定证据 ID、项目、提交、仓库相对路径、符号、起止行、块 ID、受限摘录。
- 不得在证据对象中暴露向量、绝对本地路径、凭据或无限长度正文。

### R2. 本次检索白名单

- 每次 `RetrievalBundle` 建立独立 `EvidenceRegistry`。
- 模型和前端只能引用该注册表中的证据 ID。
- 未知、跨项目、跨版本或格式错误的 ID 必须被过滤，并产生稳定、安全的 warning。
- 重复 ID 必须去重，保留确定性顺序。

### R3. 同步开发方案引用

- 模型生成的摘要、产品理解、开发约束、链路、开发环节、实施顺序和风险应携带 `evidenceIds`。
- 服务端验证后返回逐条引用状态：`SUPPORTED`、`PARTIAL` 或 `UNSUPPORTED`。
- 现有同步 JSON 字段保持兼容；引用信息以新增字段返回。
- 缺少或非法引用不导致整次请求失败，但整体状态至少降级为 `DEGRADED`，并返回引用质量摘要和 warning。

### R4. SSE 引用一致性

- 流式 prompt 为每个可展示结论提供证据 ID 输出约束。
- SSE 服务端在事件发送前统一校验 `evidenceIds`，非法 ID 不得进入浏览器。
- `references` 事件保留现有 `documents` 和 `code`，并新增与同步接口相同结构的统一证据列表。
- `completed` 事件返回引用质量摘要和聚合后的引用 warning。
- 保持 `started`、`retrieval`、`references`、`completed`、`error` 等现有事件兼容。

### R5. 页面可追溯展示

- 开发方案页面显示引用覆盖情况和每条结论的支持状态。
- 证据 ID 渲染为可点击标签。
- 需求证据打开受限摘录面板；代码证据复用现有源码抽屉并定位到对应行。
- 页面兼容旧 SSE：没有引用字段时仍可展示原有文本，不执行不安全的 HTML 插入。

### R6. 测试与安全

- 单元测试覆盖稳定 ID、白名单过滤、重复去重、缺失引用、部分有效引用和路径/摘录清洗。
- 同步与 SSE 测试验证使用同一 `EvidenceRef` JSON 结构。
- 页面契约测试覆盖引用质量、证据标签和文档/代码打开行为。
- 测试仅使用通用虚构数据，不写入真实项目需求、向量库数据、私有路径或凭据。

## Acceptance Criteria

- [ ] 非法证据 ID 被服务端过滤，响应包含稳定 warning，浏览器无法收到该非法 ID。
- [ ] 没有引用的生成结论被标记为 `UNSUPPORTED`，部分合法引用被标记为 `PARTIAL`。
- [ ] 同步 JSON 与 SSE `references` 使用相同的 `EvidenceRef` 字段结构。
- [ ] 响应包含可解释的引用质量摘要，覆盖率可由支持条目数确定性计算。
- [ ] 前端可从引用标签打开需求摘录或对应代码位置，并兼容无引用的旧事件。
- [ ] 现有冲突报告、检索诊断、同步字段和 SSE 事件名称保持兼容。
- [ ] JDK 21 下 `./mvnw -B verify` 与 `git diff --check` 通过。
- [ ] 变更中不包含真实项目内容、需求快照、向量数据、绝对私有路径或凭据。

## Out of Scope

- 不持久化完整证据图或向量数据。
- 不新增证据人工审核工作流。
- 不在本任务内重做 Wiki 生成器、AST 索引或大文档 Map-Reduce。
- 不把“引用存在”当作事实绝对正确；本任务验证引用合法性和覆盖度，来源冲突仍由现有冲突检测负责。

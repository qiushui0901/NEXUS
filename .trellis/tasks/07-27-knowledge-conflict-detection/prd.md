# 统一知识冲突检测

## Goal

在需求、代码、测试与派生 Wiki 之间建立可复用、版本化、可追溯的知识声明与冲突检测基础能力，确保 RAG 和 Wiki 遇到不一致时不会静默合并或伪装成确定事实。

## Requirements

- 需求、代码、测试属于原始来源；Wiki 属于派生来源，不能覆盖原始证据。
- 每条参与比较的知识声明必须包含项目、版本、事实键、事实值、来源类型和证据标识。
- 仅比较同一项目、同一版本、同一事实键的声明；不同事实值形成候选冲突。
- 派生 Wiki 声明没有原始证据时应形成阻断问题；与原始来源不一致时应标记为过期冲突。
- 冲突不得自动仲裁或修改原始证据，响应必须保留各来源独立结论。
- 冲突报告必须区分需求与代码、需求与测试、代码与测试、Wiki 与原始证据、同类来源内部冲突和版本污染。
- 提供受项目权限保护的分析 API，并在开发方案 RAG 响应中返回检索证据的版本一致性/来源冲突报告。
- 现有 API 字段保持兼容，只允许追加字段。
- 不持久化向量、原始项目文档、代码正文、凭据或具体项目知识数据。

## Acceptance Criteria

- [x] 有统一的 `KnowledgeClaim`、`KnowledgeConflict`、`KnowledgeConflictReport` 契约。
- [x] 冲突服务能够稳定检测相同事实键的不同值，并对重复声明去重。
- [x] 能检测目标版本与证据版本不一致的版本污染。
- [x] 能识别无原始证据的派生 Wiki 声明以及 Wiki 与原始来源不一致。
- [x] 冲突报告包含严重程度、状态、涉及证据和安全的用户提示，不包含内部异常。
- [x] `POST /api/knowledge/conflicts/analyze` 校验项目权限并返回确定性报告。
- [x] 非流式开发方案响应追加冲突报告，不破坏已有字段和构造方式。
- [x] 单元测试覆盖无冲突、跨来源冲突、同源冲突、Wiki 无证据、版本污染、重复声明和控制器权限。
- [x] JDK 21 Maven 验证与 `git diff --check` 通过。

## Constraints

- 第一版只比较已经结构化的声明，并对检索证据做确定性的版本一致性检查；不使用模型猜测两个自由文本片段是否语义冲突。
- 第一版不实现冲突持久化、人工仲裁页面和自动修改 Wiki；这些能力以后基于当前契约扩展。
- 测试数据必须通用、匿名，不包含用户具体项目内容。
